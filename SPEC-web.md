# Spec: web

Карта: [SPEC.md → Capability Map](SPEC.md#capability-map). Зависит от: всех модулей.
Собирается вертикальными срезами вместе с ними.

## Objective

Локальное веб-приложение (FastAPI + Jinja2 + HTMX) на `127.0.0.1:8000`, три страницы.

## Страницы

| Путь | Содержимое | Срез |
|---|---|---|
| `/` | Чат чек-ина; над чатом карточка активного эксперимента (день N из 7) | после `checkin` |
| `/checkin/form` | Запасная форма чек-ина (те же поля и валидация) | после `checkin` |
| `/history` | Таблица записей (правка/удаление) + графики энергии, настроения и сна (Chart.js) + блок «Связи» | после `insights` |
| `/experiments` | Предложение (принять/другой), активный эксперимент, архив с отчётами | после `experiments` |

## HTMX-эндпоинты (возвращают HTML-фрагменты)

- `POST /chat` → новое сообщение пользователя → фрагмент с ответом агента.
- `POST /checkin/confirm` → сохранить черновик → фрагмент «Сохранено».
- `POST /experiments/{id}/accept|reject|abandon`.
- `DELETE /entries/{day}`, `PUT /entries/{day}`.

Черновик чек-ина и история чата хранятся в памяти процесса: пользователь один,
приложение локальное. После перезапуска сервера чат начинается заново, сохранённые
записи остаются.

## Требования

- Без авторизации; сервер слушает только `127.0.0.1`.
- Мобильная ширина не обязательна, но страница не ломается на 375 px.
- Ошибки валидации видны у поля, а не как 500.
- Ключ API не попадает в HTML и логи.
- HTMX лежит в проекте (`/static/htmx.min.js`), а не на CDN: приложение работает без интернета
  везде, кроме LLM-чата (Success Criteria №6).
- Без JavaScript всё тоже работает: обычные формы, после POST — редирект 303 на `/`.

## Acceptance Criteria

1. `uv run uvicorn biohucker.web.app:create_app --factory` поднимает приложение на пустой БД без ошибок.
2. Каждый срез проверен через `TestClient`: страница отдаёт 200, основной сценарий проходит на `FakeLLM`.
3. При `degraded` на `/` есть заметная ссылка на форму.
