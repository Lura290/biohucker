# Spec: checkin

Карта: [SPEC.md → Capability Map](SPEC.md#capability-map). Зависит от: `journal`, `llm`.

## Objective

Ежедневный опрос в чате: собрать запись за сегодня за минимум реплик, переспросить
только недостающее, показать итог и сохранить после подтверждения.

## Диалог

1. Пользователь открывает страницу. Если за сегодня записи нет, агент пишет первым
   одно сообщение со всеми вопросами списком и добавляет: «можно ответить одной фразой».
2. Ответ пользователя → `llm.run` с инструментами ниже.
3. Модель вызывает `propose_checkin` с тем, что удалось извлечь. Код считает
   недостающие поля. Если они есть, агент спрашивает **только их**, одним сообщением.
4. Когда всё собрано или пользователь сказал «остальное пропусти», агент показывает итог
   (таблица полей) с кнопками «Сохранить» / «Исправить».
5. «Сохранить» → `journal.upsert`, без LLM. Запись в БД делает код по кнопке, не модель.
6. Если активен эксперимент, добавляется вопрос «Выполнил сегодня: <название>?».

Если запись за сегодня уже есть, агент не опрашивает. Он показывает запись и
предлагает изменить её.

## Инструменты для модели

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `propose_checkin` | частичный `CheckinEntry` без `day` | сохраняет черновик в сессии, возвращает список недостающих полей |
| `get_today_context` | — | дата, есть ли активный эксперимент и его название |

Модели **не дают** инструмент записи в БД. Так она не может сохранить что-то без
подтверждения.

## Промпт (суть)

- Роль: короткий дружелюбный опросник, не врач и не коуч. Ответы ≤ 2 предложений.
- Относительные выражения («в полночь», «около 7») переводить во время; «не гулял» → 0.
- На вопросы о здоровье, лекарствах, добавках — отказ и совет обратиться к врачу.
- Не комментировать и не оценивать ответы (без «маловато сна!») — анализ делает `insights`.

## Деградация

`degraded=True` или пользователь нажал «Заполнить формой» → обычная HTML-форма с теми же
полями и той же валидацией.

## Acceptance Criteria

1. Полный ответ одной фразой → итог на подтверждение после **1** ответа модели.
2. Неполный ответ → ровно одно уточняющее сообщение, перечисляющее только недостающие поля.
3. Без нажатия «Сохранить» в БД ничего не появляется.
4. Невалидное значение («энергия 15») → переспрос этого поля, в черновик не попадает.
5. Вопрос «какой магний пить?» → отказ без названий препаратов и дозировок.
6. При `degraded` пользователь может сохранить запись формой.

## Тесты

Integration на `FakeLLM`: сценарии 1–4 и 6. Эвалы (`-m eval`, реальная модель): 5 фраз
разной формы → корректный черновик; сценарий 5; переспрос недостающего.
